# AGENTS.md — Lữ Trình (Android)

Lữ Trình (`vn.lutrinh.app`) is a local-only travel journal for Vietnam: trips → steps (place on an
OpenStreetMap map, date/time, note, photos) shown as a timeline and a route map. Native Android
now (Kotlin, Compose M3, Room, MapLibre, Coil 3); an iOS/Swift port will follow, built from `docs/`.
No server or login in this phase. One exception (R36): while "Tính đường đi" is on (default,
one-time notice, switch in "Cài đặt") the two stop positions + travel mode of each road leg go to
the OpenStreetMap routing server (FOSSGIS Valhalla, OSRM car fallback); nothing else leaves the device.

## Standing rule

**Every behaviour change updates `docs/01`–`07`** (the platform-neutral spec the iOS app is built
from) in the same branch: rules R1–R37 in `docs/04` with their test names, screens in `docs/03`,
map in `docs/05`, photos in `docs/06`, and the Swift equivalent in `docs/07-ios-port.md`. Add a
screenshot to `docs/img/` (and the index in `docs/03`) when a screen changes.

**Every screen, popup and change of look, now and later, follows `docs/08-design.md`** ("Topo
outdoor", after the huashu-design specimen 06-topo-outdoor, captain 2026-11-10): Parchment topo
paper + Card panels with a 2 dp `ledge()`, Forest dark chip for the main action, one Signal-orange
route, Noto Sans + Barlow Condensed numerals, radii 8/12/18/22 (`Radii`), soft shadows (`Lift`)
only over the map, `TopoIcons` only, real photos only. Colours only in `ui/theme/` (`Palette`; map
code uses `Color.rgbHex()`); `DesignGuardTest` (in `testDebugUnitTest`) fails on colour literals,
gradients, raw corner radii or shadows outside the tokens, FABs outside `Buttons.kt`, other fonts,
and Material icons / off-scale weights outside its `notYetTopo` list (= the files `docs/09` still
lists for a later batch: remove a file from it when you redo it). A new token or text/background
pair goes into the docs/08 contrast table.

## Build and test

```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home
export ANDROID_HOME=/Volumes/wdblack/flutter/android-sdk
export GRADLE_USER_HOME=/Volumes/wdblack/tmp/gradle-home
export TMPDIR=/Volumes/wdblack/tmp/<task>; mkdir -p "$TMPDIR"   # <task> = your crew/worktree name
./gradlew clean assembleDebug testDebugUnitTest compileDebugAndroidTestKotlin   # the gate
ANDROID_SERIAL=emulator-5580 ./gradlew connectedDebugAndroidTest   # UI tests on the AVD below
```

**Builds, caches and scratch live on `/Volumes/wdblack/tmp` (captain 2026-11-10), never `/tmp`,
`/private/tmp` or `~/.gradle`:**

* Gradle user home = `/Volumes/wdblack/tmp/gradle-home` and scratch = `$TMPDIR` as above, in every shell.
* Project build output: root `build.gradle.kts` redirects every module to
  `/Volumes/wdblack/tmp/lutrinh-build/<checkout dir name>/<module>`, so each worktree has its own
  (nothing is written to `build/` or `app/build/` any more). Override with
  `-Plutrinh.buildRoot=<dir>` or env `LUTRINH_BUILD_ROOT`; if the disk is absent the default `build/`
  is used. `./gradlew -q printBuildDir` prints the resolved dirs.
* The debug APK is `/Volumes/wdblack/tmp/lutrinh-build/<checkout dir name>/app/outputs/apk/debug/app-debug.apk`
  (reports: `.../app/reports/`).
* APKs, screenshots, scripts, recordings and DB copies go under `/Volumes/wdblack/tmp/<task>/`.
* Before any install: `export ANDROID_SERIAL=<your own device>` (see Emulator and Traps).

`connectedDebugAndroidTest` uninstalls the app afterwards (app data is gone); run `installDebug`
again before manual checks.

## Traps

* zsh does not word-split `ADB="adb -s emulator-5580"`; call the full adb path with `-s`.
* `adb shell input text` cannot type Vietnamese diacritics (use ASCII, or Compose tests, which can).
* `*.openstreetmap.org` resets TLS from this network → the basemap is the OpenFreeMap vector
  style (`Positron.STYLE_URL` in `map/basemap/OpenFreeMap.kt`, `curl -sI` it first). Repaint ids
  in `Positron.REPAINT` are Positron layer ids; another style needs its own ids.
* Satellite (R32/R33): Esri imagery is keyless unless `esriApiKey=` is in `local.properties`
  (git-ignored, never commit a key; a git grep for the key prefix must find nothing). Switch styles on the AVD
  with the layers button ("Kiểu bản đồ" content description); check the choice with
  `run-as vn.lutrinh.app cat shared_prefs/lutrinh_prefs.xml | grep map_style`. Leave the captain's
  AVD at `light`.
* Map screenshots by script: pinch needs root; zoom in with a double tap
  (`input tap x y; sleep 0.1; input tap x y` — without the sleep it is two single taps) and out
  with a quick-scale (`input motionevent DOWN/UP/DOWN`, MOVE upwards, UP).
* Location permissions are real since GPS tracks (R16): fine/coarse + `FOREGROUND_SERVICE_LOCATION`
  + `POST_NOTIFICATIONS`; `ACCESS_BACKGROUND_LOCATION` stays removed with `tools:node="remove"`
  (check: `aapt dump permissions app-debug.apk`). Never ask for background location.
* GPS on the emulator (R16): `adb -s emulator-5580 emu geo fix <lon> <lat>` (longitude first)
  feeds the platform GPS provider the recorder uses. Send fixes ≥ 6 s apart and ≥ 10 m apart (the
  filter drops closer ones; > 85 m/s between fixes = dropped as a jump). Log:
  `logcat -s TrackRecording` prints each fix with its verdict. Query the DB in place (the AVD has
  `/system/bin/sqlite3`): `adb -s emulator-5580 shell 'run-as vn.lutrinh.app sqlite3
  databases/lutrinh.db "select status,point_count,distance_m from tracks"'`. A real road for
  fixes: `router.project-osrm.org/route/v1/driving/<lon,lat;lon,lat>?overview=full&geometries=geojson`
  answers from this network (OSM data), resample to ~150 m, one fix every 7 s. Screen off:
  `input keyevent 26`; back: `keyevent 224` + `wm dismiss-keyguard`. Process death:
  `am force-stop vn.lutrinh.app` (`am kill` does not kill a foreground service); the next start
  ends the track as interrupted. Notification shade: `cmd statusbar expand-notifications`.
  Fix time is the wall clock (no fake time source), so a ≥ 20-min stay for stop suggestions (R17)
  needs ~21 real minutes of fixes; alternate two points ~25 m apart every 60 s (a fix < 10 m from
  the last is dropped).
  Shortcut for a suggestion on any date: `adb push` an SQL file of `insert into tracks …` + 27
  `track_points` rows (60 s apart, two points ~25 m apart) to `/data/local/tmp`, then
  `run-as vn.lutrinh.app sh -c 'sqlite3 databases/lutrinh.db < /data/local/tmp/seed.sql'` (R17 extend-dates check).
* A Compose `Dialog` re-provides `LocalConfiguration`/`LocalContext`: locale overrides must go
  **inside** dialog content (see `VietnameseLocale`). Don't wrap the whole app: MapLibre's
  `MapView` needs the real Activity context.
* Material 3 1.3 `ExtendedFloatingActionButton` exposes no text in semantics; label it with a
  content description (tests and TalkBack rely on it).
* uiautomator substring matches are greedy ("Bỏ" also matches "Bỏ các thay đổi?") — match exact
  text when tapping dialogs by script.
* The Android **Photo Picker hides EXIF GPS** (even with `ACCESS_MEDIA_LOCATION`;
  `setRequireOriginal` throws on picker URIs). "Thêm từ ảnh" therefore uses `ACTION_OPEN_DOCUMENT`
  + `ACCESS_MEDIA_LOCATION` (docs/06). On API 34+ that permission shows the "photos and videos"
  dialog; "limited access" first opens a selection sheet. Read GPS **before**
  `PhotoStorage.import` — the stored copy has none (R11).
* MapLibre `line-dasharray` is not data-driven: one `LineLayer` per dash kind, filtered by `mode`.
* Room schema bump = bump `AppDatabase.VERSION`, add `MIGRATION_x_y` to `MIGRATIONS`, commit
  `app/schemas/.../<v>.json`, extend `MigrationTest` (no destructive fallback, on purpose).
* Gboard on emulator-5580 shows a "Try out your stylus" popup on scripted taps; it swallows
  `adb shell input text`. Dismiss the onboarding once by hand-tap, or enter text with Compose tests. The popup is a Gboard window that uiautomator does not list: tap its "Cancel" by coordinates (about 55% x, 95% y of the screen), then tap the field and type again.
* **Screenshots and manual checks run on your own AVD, never on emulator-5580** (it holds the
  captain's data: do not install, seed or screenshot there). Create one named after your worktree
  (`avdmanager create avd -n <worktree-dir> -k 'system-images;android-36;google_apis;arm64-v8a' -d pixel_6`),
  start it on a free port (`emulator -avd <name> -port 559x -no-window -no-audio -no-snapshot`), set
  `persist.sys.locale vi-VN` if you need Vietnamese system text, and seed sample data via the debug
  build. Record the 5580 DB counts before/after when a task forbids touching it.
* The emulator is shared: another crew's `install -r` replaces your APK within seconds (check `pm path` + `unzip -l` for a resource of yours, e.g. `noto_sans`) — reinstall right before each screenshot batch and script the whole batch in one command.
* Dates, km and durations: only `domain/usecase/DisplayFormat.kt` (docs/03 "Display conventions"); never
  `String.format(Locale.US, …)` in `ui/`. The theme is light-only, so `MainActivity` forces the light
  system-bar style; a screen with a dark background (photo viewer) flips the status-bar icons itself.
* `adb shell input text` into a Compose field: wait ~1.5 s after tapping it, select all with
  `input keycombination 113 29`, then type.
* Test JPEGs with GPS/date: write the EXIF with a small script (APP1 with IFD0 + Exif + GPS IFDs),
  `adb push` to `/sdcard/Pictures/…`, then per file

  Pushed files get **`datetaken` NULL** in MediaStore (EXIF date has no offset, mtime = push time),

  --projection _id:_display_name:datetaken | grep <name>` (`--where` with LIKE fails). Media access
